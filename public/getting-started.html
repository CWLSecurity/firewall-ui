Getting Started Guide

How to start using Firewall Vault

This guide explains the real user flow: connect a wallet, create or import a Vault, fund it, and then use the Vault for protected actions on Base.

Your wallet Used for login and signatures.
Your Vault Holds funds and applies protection rules.
Your queue Delayed actions wait here until unlock time.
Visual model

Step-by-step setup

1

Connect a wallet

Use a wallet you already control, such as MetaMask or Rabby.

  1. Click Connect Wallet.
  2. Approve the connection in your wallet extension.
  3. Switch to Base Mainnet if the site asks you to.
What happens here

Your wallet becomes the signer. It does not automatically become the Vault.

2

Create or import a Vault

Create a new protected Vault or reconnect one you already use.

  1. Choose Create New Vault if this is your first setup.
  2. Choose Import Existing Vault if you already created one before.
  3. Creating a Vault requires one on-chain setup transaction.
Important

Your connected wallet remains your signer. The new Vault is the protected account you use inside the product.

3

Choose a protection mode

Pick the mode that matches how you plan to use the Vault.

Vault

Best for long-term storage and occasional withdrawals.

  • First transfer to a new address is delayed.
  • Large transfers are delayed.
  • Good fit when funds mostly stay parked.

DeFi Trader

Best for active DeFi usage with guardrails still in place.

  • Common DeFi approvals stay usable.
  • New spenders and risky first-time actions can still be delayed.
  • Good fit for swaps, bridging, and protocol usage.
4

Fund the Vault

Move ETH or tokens into the Vault before using it.

  1. Open Receive.
  2. Copy the Vault address or use the direct-send action.
  3. Send ETH or supported assets into the Vault.
Good mental model

You do not send from your signer wallet directly in normal use. You fund the Vault, then act from the Vault.

Using the Vault after setup

Send from Vault When you send from the Vault, the action is checked by on-chain protection rules.
↓
If the action is safe It proceeds immediately.
↓
If the action is risky It may be delayed and moved into the queue until its unlock time.
↓
After unlock You can execute it yourself, or let automation execute it if enabled.

Queue and automation

The queue is where delayed actions wait. Automation is optional and only helps execute actions after they have already unlocked.

Automation does not bypass delays Automation does not withdraw arbitrary funds Automation only helps with already-unlocked queued actions
Why there is an automation balance

The setup flow asks for an initial automation balance so delayed actions can be auto-executed later without giving the automation service free access to your Vault balance.

Common questions

What is the difference between my wallet and my Vault?

Your wallet is the signer you connect in the browser. The Vault is the protected on-chain account that holds funds and applies rules to outgoing actions.

Why did my transfer go to the queue?

It matched an active protection rule, such as a large transfer or a first transfer to a new address. The queue gives you a review window before the action can execute.

Do I need to create a new Vault every time I connect?

No. If you already created a Vault for this signer, use Import Existing Vault or let the site detect it.

Should I choose Vault or DeFi Trader?

Choose Vault if the account mostly stores assets. Choose DeFi Trader if you plan to use protocols often and need a more DeFi-friendly mode.
